# Trip Pocket 분석 및 설계

## 1. 프로젝트 목표

여행을 준비하는 개인 사용자가 가고 싶은 장소와 다녀온 장소를 한곳에 기록하고, 다음 여행 일정을 빠르게 확인할 수 있는 웹앱을 만든다.

## 2. 핵심 사용자와 문제

- 사용자: 여행지를 메모 앱이나 SNS 저장 기능에 흩어 보관하는 개인 여행자
- 문제: 저장한 장소를 다시 찾기 어렵고 방문 여부와 날짜를 함께 관리하기 어렵다.
- 해결: 장소명, 도시, 카테고리, 날짜, 메모, 방문 상태를 하나의 카드로 관리한다.

## 3. MVP 범위

- 여행지 등록, 조회, 수정, 삭제
- 장소명·국가·도시·메모 통합 검색
- 방문 상태 및 카테고리 필터
- 가고 싶은 곳과 다녀온 곳 상태 전환
- 저장 개수와 가장 가까운 여행 D-Day 표시
- PostgreSQL을 이용한 영구 데이터 저장
- 이메일 회원가입·로그인·로그아웃
- 로그인 계정별 여행지 데이터 분리
- 여행별 장소 묶음, 우선순위와 예상 비용 관리
- 여행 필터와 다양한 정렬, 지도 검색 연결
- 모바일 및 데스크톱 반응형 화면

지도, 사진 업로드, 동행자 공유, 외부 여행 API는 다음 단계로 제외한다.

## 4. 주요 사용자 흐름

1. 사용자가 이메일과 비밀번호로 가입하거나 로그인한다.
2. 홈에서 자신의 여행지와 다가오는 일정을 확인한다.
3. `여행지 추가`를 눌러 장소 정보와 메모를 입력한다.
4. 저장된 카드를 검색하거나 상태·카테고리로 필터링한다.
5. 여행 후 카드를 `다녀온 곳`으로 변경한다.
6. 필요한 경우 내용을 수정하거나 삭제한다.

## 5. 데이터 모델

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| id | string | 여행지 고유 식별자 |
| name | string | 장소명 |
| country | string | 국가 |
| city | string | 도시 |
| category | enum | 관광지, 자연, 맛집, 숙소, 휴양, 기타 |
| status | enum | wishlist 또는 visited |
| tripName | string | 장소가 속한 여행 이름 |
| priority | enum | must, interested 또는 later |
| estimatedCost | integer | 장소별 예상 비용(원) |
| visitDate | date string | 방문일 또는 방문 예정일 |
| memo | string | 개인 메모 |
| createdAt | ISO date string | 생성 시각 |
| userId | UUID | 여행지를 소유한 사용자 식별자 |

사용자 정보는 `users`, 로그인 세션은 `sessions` 테이블에 저장한다. 비밀번호는
scrypt 해시만 저장하며, 브라우저에는 원본 세션 토큰을 HttpOnly 쿠키로 전달한다.
데이터베이스에는 세션 토큰 원문 대신 SHA-256 해시를 저장한다.

## 6. 화면 설계

- 인증 화면: 로그인·회원가입 전환, 입력 검증, 오류 안내
- 상단: 서비스 이름, 사용자 정보, 로그아웃과 여행지 추가 버튼
- 요약 영역: 서비스 설명, 전체 개수, 상태별 개수, 다음 여행 D-Day
- 도구 영역: 검색, 여행·카테고리·방문 상태 필터, 정렬
- 콘텐츠 영역: 반응형 여행지 카드와 빈 검색 결과 안내
- 입력 모달: 장소·여행 이름·우선순위·예상 비용 입력, 검증 메시지, 저장 및 취소
- 피드백: 저장·수정·삭제·상태 변경 완료 알림

## 7. 기술 설계

- Next.js App Router와 TypeScript
- 정적 페이지에서 상호작용 영역만 Client Component로 구성
- React state로 화면 상태 관리
- Next.js Route Handler로 PostgreSQL CRUD API 제공
- `pg` 커넥션 풀을 서버 전용 모듈에서 관리
- Route Handler에서 세션을 검증하고 모든 여행지 쿼리를 사용자 ID로 제한
- Tailwind CSS와 CSS 디자인 토큰으로 일관된 스타일 구성

## 8. 향후 확장

1. 이메일 인증과 비밀번호 재설정
2. 지도에서 여행지 위치 선택
3. 여행별 일정 그룹과 날짜별 정렬
4. 이미지 업로드
5. 동행자 초대와 일정 공유
